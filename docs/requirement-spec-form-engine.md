# 需求规格说明书：动态表单引擎

> 版本：v1.1
> 日期：2026-07-31
> 状态：待评审
> 修订依据：需求访谈 — 基于设计评审报告缺口进行认知对齐

---

## 1. 背景

企业级业务系统中存在大量表单需求，涵盖从简单信息采集到复杂多步骤审批流程。当前状况下：

- 每个表单需要独立开发前端代码，中等复杂度表单开发周期需 2–3 天
- 需求调整时修改成本高，牵一发而动全身
- 各表单样式和交互难以统一，用户体验参差不齐
- 业务人员无技术能力，无法自主创建和维护表单，必须依赖开发团队

这些痛点导致业务响应速度慢、IT 资源被重复消耗、用户满意度低。

---

## 2. 业务目标

建设一套**配置驱动的动态表单引擎**，实现：

1. **业务自助化**：零代码能力的业务人员可自主设计、发布表单模板，无需开发介入
2. **统一用户体验**：所有表单由引擎统一渲染，确保交互和视觉一致性
3. **快速响应变更**：表单结构调整只需修改配置，无需重新开发和部署
4. **审批流内置**：表单与审批链深度整合，提交后自动进入工作流流转

如果本系统不建设：
- 业务部门持续依赖 IT 排期，表单需求响应周期长
- 各业务线表单样式割裂，维护成本持续攀升
- 无法支撑企业数字化转型中表单需求的快速增长

---

## 3. 环境模型

系统采用**四环境隔离**逐级晋升，以环境和角色分离替代传统的审批流程：

```
DEV  →  系统开发者构建表单引擎本身
SIT  →  系统开发者集成测试
UAT  →  模板设计者制作模板，发布后邀请小范围业务用户测试验证
PROD →  运维人员将 UAT 验证过的模板迁移至生产环境，正式服役
```

| 环境 | 谁在操作 | 做什么 |
|------|---------|--------|
| DEV / SIT | 系统开发者 | 开发表单引擎功能 |
| UAT | 模板设计者 + 测试填写者 | 设计模板、暂存、发布、邀请测试、迭代修改 |
| PROD | 运维人员 + 正式用户 | 导入迁移的模板、正式填写使用、下架/上架管理 |

**质量门控机制**：模板在 UAT 经过充分测试验证后，由运维人员迁移至 PROD。模板本身**不存在审批流程**——环境的隔离与逐级晋升即构成质量保障。

## 4. 术语定义

| 术语 | 执行角色 | 含义 | 作用域 |
|------|---------|------|--------|
| **暂存** | 模板设计者 | 将编辑中的模板保存至服务器，尚未对外可见 | 当前环境 |
| **本地自动暂存** | 系统自动 | 浏览器端 localStorage/IndexedDB 自动保存，防断电崩溃 | 本地浏览器 |
| **发布** | 模板设计者 | 将模板设为可见，用户可浏览并填写提交 | 当前环境内 |
| **下架** | 有权限者 | 将已发布模板隐藏，不再接受新提交，历史实例仍可查看 | 当前环境内 |
| **上架** | 有权限者 | 将已下架模板重新设为可见 | 当前环境内 |
| **迁移** | 运维人员 | 将 UAT 模板配置导入 PROD，使其在 PROD 上线 | 跨环境（UAT → PROD） |
| **导出** | 模板设计者 | 将模板配置导出为文件（JSON），作为迁移的载体 | UAT → 文件 |
| **导入** | 运维人员 | 将导出的模板配置文件导入 PROD | 文件 → PROD |

## 5. 用户角色

| 角色 | 说明 | 典型用户 |
|------|------|---------|
| **模板设计者** | 零代码能力者，在 UAT 环境使用设计器创建、暂存、发布、下架、上架表单模板 | 部门管理员、业务流程负责人 |
| **表单填写者** | 内部员工，浏览可用表单并填写提交 | 全体内部员工 |
| **审批人** | 审批链路上的参与者，对**表单实例**进行审批操作 | 直属上级、IT 部门负责人等 |
| **运维人员** | 在 PROD 环境执行模板导入（迁移）、下架、上架等操作 | IT 运维人员 |
| **系统管理员** | 管理系统用户、角色权限、系统配置 | IT 运维人员 |

> **说明**：角色权限采用自定义配置模式，非硬编码。管理员可定义角色并分配能力。
>
> **变更说明（v1.1）**：移除"模板审批人"角色——模板本身不存在审批流程，质量保障通过 UAT → PROD 环境晋升实现。

### 各角色核心诉求

| 角色 | 核心诉求 |
|------|---------|
| 模板设计者 | 通过可视化工具快速创建表单；暂存应对中断场景；发布后邀请 UAT 用户测试；编辑时锁定防冲突；可将模板配置导出供运维迁移 |
| 表单填写者 | 浏览可用表单，在 PC 和移动端均可完整填写；支持保存草稿；提交后可查看审批进度 |
| 审批人 | 接收审批通知，查看表单内容并做出审批决定（同意/拒绝/退回/转交） |
| 运维人员 | 在 PROD 导入模板配置完成迁移；管理模板上架/下架 |
| 系统管理员 | 管理用户和角色权限，查看全局数据和统计 |

## 7. 业务规则

### 7.1 模板生命周期规则

| 编号 | 规则 |
|------|------|
| BR-01 | 表单模板采用签出/签入机制，同一时间仅允许一人编辑 |
| BR-02 | 模板设计者可在编辑过程中将模板**暂存**至服务器，暂存的模板对其他设计者可见但不可编辑（除非签出） |
| BR-03 | 暂存时同时清空本地浏览器自动暂存数据 |
| BR-04 | 浏览器端提供本地自动暂存（localStorage / IndexedDB），防断电或浏览器崩溃；打开模板时如检测到未恢复的本地暂存数据，提示用户恢复 |
| BR-05 | 模板**发布**后方可在当前环境中对用户可见、可填写 |
| BR-06 | 模板**下架**后：在可用表单列表中隐藏；历史已提交实例仍可查看（按提交时的模板快照渲染）；已提交实例的数据仍可查询和导出；不可再提交新实例 |
| BR-07 | 模板下架为**可逆操作**——已下架的模板可重新上架恢复可见 |
| BR-08 | 模板发布后，不影响已提交和正在填写的表单实例（实例绑定提交时的模板快照） |
| BR-09 | 模板配置以可导出文件形式在环境间迁移（DEV → SIT → UAT → PROD） |
| BR-10 | 模板迁移由**运维人员**在 PROD 环境执行导入操作 |
| BR-11 | 模板迁移仅迁移配置本身，不包含 UAT 的测试提交数据 |
| BR-12 | 迁移后 UAT 原模板保留不动 |
| BR-13 | 同一模板再次迁移时，PROD 旧版本自动下架，新版本上线 |
| BR-14 | UAT 中同模板 v1 → v2 发布时，与 PROD 行为一致：下架旧版本 → 上线新版本 |
| BR-15 | 草稿（表单实例草稿）保留期限为 2 年，超期自动清除 |

| **表单设计器** | 可视化拖拽编排、字段属性配置、章节管理、实时预览、签出/签入锁定、本地自动暂存、手动暂存至服务器、发布/下架/上架、配置导出 |
| **模板迁移** | PROD 导入模板配置、自动处理新旧版本替换（旧版下架 + 新版上线） |
| **审批链配置** | 多级审批节点、审批人规则定义、审批顺序编排 |
| **字段类型** | 文本输入、多行文本、数字输入、下拉框、单选按钮、多选框、日期、日期时间、文件上传、子表单/表格、人员选择器、带图标样式的信息文本（提示/警告/危险） |
| **字段联动** | 字段级/章节级显示隐藏条件、AND/OR 嵌套、可视化条件编辑器 |
| **字段验证** | 必填、长度、范围、正则、文件类型/大小/数量、跨字段验证 |
| **表单填写器** | 表单列表浏览、表单填写（PC + 移动端响应式）、草稿保存、提交、撤回 |
| **审批界面** | 表单内容 + 审批链状态同屏展示、同意/拒绝/填写意见/退回/转交 |
| **通知机制** | 上述 5 类事件通知（实例提交、审批结果、转交、撤回、审批完成） |
| **数据管理** | 提交数据列表查看、Excel 导出、按表单类型统计 |
| **权限管理** | 自定义角色、能力分配 |
| **数据隔离** | 按用户角色和审批链路隔离数据可见性 |
| **草稿管理** | 保存草稿、2 年保留期限 |
| **历史实例** | 基于模板快照渲染、关联旧模板名称、数据可查询导出 |

## 9. 非功能需求

| 编号 | 类别 | 需求 |
|------|------|------|
| NFR-01 | **规模** | 支持 ≥20 个活跃表单模板，单个模板 10–30 个字段 |
| NFR-02 | **吞吐** | 日均表单提交量 ≥100 |
| NFR-03 | **并发** | 同时在线填写者峰值 ≥50 人 |
| NFR-04 | **响应式** | 填写端 UI 适配 PC 和移动端（完整填写 + 审批操作） |
| NFR-05 | **可用性** | 表单设计器面向零代码用户，交互直觉化，学习成本低 |
| NFR-06 | **数据一致性** | 表单模板变更不影响已提交和进行中的实例 |
| NFR-07 | **配置可移植** | 表单配置可在环境间以文件形式迁移部署 |
| NFR-08 | **权限灵活** | 角色和权限可自定义，非硬编码 |
