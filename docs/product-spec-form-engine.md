## 1. 产品概述

### 1.1 产品定义

**产品名称**：动态表单引擎

**一句话描述**：让业务人员零代码自主创建表单、配置审批流程，终端用户在一个统一界面完成填写与审批追踪的配置驱动型表单系统。

**产品分类**：企业效能工具 / 业务流程平台

---

## 2. 功能定义

本产品包含以下核心功能模块。每个功能模块独立定义，但协同工作以交付端到端的表单管理体验。

| 功能编号 | 功能名称 | 简述 |
|---------|---------|------|
| F1 | 表单设计器 | 可视化拖拽编排表单结构与审批链，实时预览，配置导出迁移 |
| F2 | 表单填写器 | 浏览、填写、提交表单，查看审批进度，保存草稿 |
| F3 | 审批工作流 | 多级审批流转，审批操作（同意/拒绝/退回/转交），进度可见 |
| F4 | 数据管理 | 表单数据查看、导出、统计分析 |
| F5 | 通知系统 | 关键事件消息推送 |
| F6 | 权限管理 | 自定义角色与能力分配 |

## 3. F1 — 表单设计器

### 3.1 功能定义

| 属性 | 内容 |
|------|------|
| **功能名称** | 表单设计器 |
| **业务目标** | 使零代码能力的业务人员能够自主创建、编辑和维护表单模板，消除对开发团队的依赖 |
| **用户价值** | 表单创建周期从 2–3 天缩短至分钟级；业务人员掌握表单创建主动权；样式和交互自动统一 |

### 3.2 用户故事

- 作为**表单设计者**，我想要**创建一个空白表单模板并设置名称、描述和分类**，以便建立表单的基础元数据。
- 作为**表单设计者**，我想要**从组件面板拖拽字段到画布上，自由调整字段顺序和层级**，以便可视化编排表单结构。
- 作为**表单设计者**，我想要**选中任意字段后在属性面板配置其标签、提示文本、默认值、验证规则和是否必填**，以便精确控制字段行为。
- 作为**表单设计者**，我想要**创建和管理章节（字段分组），支持折叠/展开**，以便组织复杂表单的布局层次。
- 作为**表单设计者**，我想要**在可视化条件编辑器中配置字段和章节的显示/隐藏规则，支持嵌套 AND/OR 组合**，以便根据上下文动态控制表单显示。
- 作为**表单设计者**，我想要**在设计过程中，右侧面板实时渲染填写态预览**，以便即时验证设计效果并发现配置问题。
- 作为**表单设计者**，我想要**签出表单模板获得独占编辑权，编辑完成后签入**，以便防止多人同时编辑导致的冲突覆盖。
- 作为**表单设计者**，我想要**将表单配置导出为可迁移文件，并可导入到其他环境**，以便通过 DEV→SIT→UAT→PROD 的逐级验证后安全上线。
- 作为**表单设计者**，我想要**为表单模板配置多级审批链规则（组织架构/角色/指定人员）**，以便提交后自动触发审批流转。

### 3.3 验收标准

#### AC-F1-01：创建表单模板

| 条件 | 描述 |
|------|------|
| **Given** | 用户已登录系统并具有表单设计者权限 |
| **When** | 用户点击"新建表单模板"，输入名称、描述、选择分类，点击"创建" |
| **Then** | 系统创建空白模板，用户进入设计器界面并自动签出该模板 |

#### AC-F1-02：拖拽添加字段

| 条件 | 描述 |
|------|------|
| **Given** | 用户已打开一个处于签出状态的表单模板 |
| **When** | 用户从左侧组件面板拖拽"文本输入"字段到中间画布的指定位置 |
| **Then** | 画布上出现该字段的占位渲染，右侧预览同步显示；字段被添加到表单结构配置中 |

#### AC-F1-03：配置字段属性

| 条件 | 描述 |
|------|------|
| **Given** | 画布上已添加一个文本输入字段 |
| **When** | 用户点击该字段，在属性面板中设置标签为"设备名称"、勾选"必填"，设置最小长度 2、最大长度 50 |
| **Then** | 预览区该字段标签显示为"设备名称"并带必填标记（红色星号）；配置数据记录验证规则 |

#### AC-F1-04：配置字段联动

| 条件 | 描述 |
|------|------|
| **Given** | 表单包含一个"设备类型"下拉框（选项：办公/研发/生产）和一个"是否需要外网访问"单选框 |
| **When** | 用户在可视化条件编辑器中为"是否需要外网访问"添加显示条件：设备类型 = 研发 |
| **Then** | 预览区中，当切换"设备类型"为"办公"时，"是否需要外网访问"隐藏；切换为"研发"时显示 |

#### AC-F1-05：签出/签入锁定

| 条件 | 描述 |
|------|------|
| **Given** | 表单模板 A 已被用户甲签出编辑中 |
| **When** | 用户乙尝试打开表单模板 A 进行编辑 |
| **Then** | 系统提示"该模板正由 [用户甲] 编辑中，当前为只读模式"，用户乙无法修改 |

#### AC-F1-06：配置导出与导入

| 条件 | 描述 |
|------|------|
| **Given** | 用户在 DEV 环境完成表单模板设计并签入 |
| **When** | 用户点击"导出配置"，下载配置文件；登录 SIT 环境，点击"导入配置"，选择该文件 |
| **Then** | SIT 环境出现该表单模板的完整副本（字段、验证、联动、审批链），可在 SIT 环境继续测试 |

#### AC-F1-07：实时预览同步

| 条件 | 描述 |
|------|------|
| **Given** | 用户正在设计器中编辑表单 |
| **When** | 用户修改任意字段的标签、顺序、验证规则或联动条件 |
| **Then** | 右侧预览区在 1 秒内反映变更，提交按钮可点击并触发前端验证（模拟真实填写体验） |

### 3.4 用户流程

**主流程——创建并发布一个表单模板：**

```
1. [入口] 用户从导航菜单进入"表单管理" → 点击"新建模板"
2. [创建] 填写模板名称、描述、分类 → 点击"创建" → 自动签出
3. [编排] 从组件面板拖拽字段到画布
   - 添加章节容器，将相关字段拖入章节
   - 调整字段顺序（拖拽排序）
4. [配置] 逐个点击字段，在属性面板配置：
   - 基本属性（标签、占位提示、默认值）
   - 验证规则（必填、长度、范围、正则、文件限制）
   - 条件联动（如有依赖关系）
5. [审批] 切换到审批链配置页，添加审批节点，配置每级审批人规则
6. [预览] 在设计过程中随时查看右侧实时预览，模拟填写验证
7. [完成] 点击"签入"保存并释放锁定 → 导出配置 → 部署至目标环境
```

**错误场景：**

| 场景 | 系统行为 |
|------|---------|
| 画布中未添加任何字段，用户尝试签入 | 警告提示"表单至少需要包含一个可填写的字段" |
| 某个必填字段的标签为空 | 该字段高亮标红，属性面板提示"标签不可为空" |
| 审批链未配置任何节点 | 允许保存，但标记"该表单缺少审批配置，提交后将直接完成" |
| 导出时模板尚未签入 | 系统提示"请先签入模板后再导出" |
| 导入的配置版本高于当前系统支持的版本 | 提示"配置文件版本不兼容，请联系管理员升级系统" |

### 3.6 业务规则

| 编号 | 规则 |
|------|------|
| BR-F1-01 | 同一表单模板同时仅允许一人签出编辑 |
| BR-F1-02 | 表单模板发布后，已提交和正在填写的实例不受影响 |
| BR-F1-03 | 表单配置以可导出文件形式在环境间迁移 |
| BR-F1-04 | 画布至少包含 1 个可填写字段方可签入 |
| BR-F1-05 | 字段标签在同一个表单模板内应保持唯一（警告而非阻断） |

### 3.7 边缘情况

| 场景 | 处理策略 |
|------|---------|
| 用户长时间签出未操作（如浏览器关闭） | 签出状态保留；管理员可强制签入 |
| 画布中字段数量达到上限（如 200 个） | 提示"已达到最大字段数限制" |
| 导入的配置文件引用了当前环境不存在的字段类型 | 提示不兼容，拒绝导入 |
| 同一个字段同时被多个条件规则引用 | 所有规则独立计算，逻辑冲突时不阻断，由设计者自行检查 |
| 用户在未保存变更时关闭浏览器 | 提示"有未保存的更改，确定离开吗？" |

### 3.8 成功指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|---------|
| 零代码用户独立完成表单创建 | ≥80% 的用户无需外部协助 | 用户操作日志分析 |
| 中等复杂度表单创建时长 | ≤30 分钟（从创建到导出） | 模板创建到首次导出的时间差 |
| 设计错误率（发布后需回滚或紧急修改） | ≤10% 的模板 | 模板发布后 7 日内产生修改的比例 |
| 实时预览响应延迟 | ≤1 秒 | 操作到预览更新的端到端延迟 |

## 4. F2 — 表单填写器

### 4.1 功能定义

| 属性 | 内容 |
|------|------|
| **功能名称** | 表单填写器 |
| **业务目标** | 为终端用户提供统一的表单填写入口，支持多设备完整填写并追踪审批进度 |
| **用户价值** | 员工无需培训即可填写任何表单；在 PC 和移动端体验一致；草稿防丢、进度透明 |

### 4.2 用户故事

- 作为**表单填写者**，我想要**浏览我有权限访问的表单列表（含搜索和分类筛选）**，以便快速找到目标表单。
- 作为**表单填写者**，我想要**点击表单进入填写界面，按设计者编排的结构依次填写**，以便完成信息录入。
- 作为**表单填写者**，我想要**在填写过程中实时看到字段验证反馈（如必填未填、格式不符）**，以便提交前修正错误。
- 作为**表单填写者**，我想要**将未完成的表单保存为草稿**，以便稍后继续填写而不丢失已输入内容。
- 作为**表单填写者**，我想要**从草稿列表恢复之前的填写进度**，以便继续未完成的内容。
- 作为**表单填写者**，我想要**提交表单后在同一界面看到审批链状态（各级审批人、当前状态）**，以便了解流转进展。
- 作为**表单填写者**，我想要**在审批人尚未处理时撤回已提交的表单**，以便修正错误后重新提交。
- 作为**表单填写者**，我想要**在移动端浏览器中完整完成上述所有操作**，以便在手机和平板上工作。

### 4.3 验收标准

#### AC-F2-01：浏览并打开表单

| 条件 | 描述 |
|------|------|
| **Given** | 填写者已登录，系统中存在 3 个已发布的表单模板 |
| **When** | 用户进入"可用表单"页面 |
| **Then** | 页面显示 3 个表单卡片/列表项，包含名称、描述、分类；支持按分类筛选和名称搜索 |

#### AC-F2-02：填写并提交表单

| 条件 | 描述 |
|------|------|
| **Given** | 用户打开"设备入网报备"表单 |
| **When** | 用户完整填写所有必填字段，点击"提交" |
| **Then** | 系统校验通过后提交成功，页面切换到审批进度视图，显示"已提交，等待 [审批人] 审批" |

#### AC-F2-03：字段验证反馈

| 条件 | 描述 |
|------|------|
| **Given** | 表单中"设备名称"为必填字段，最大长度 50 |
| **When** | 用户留空"设备名称"并点击"提交" |
| **Then** | 该字段标红，显示"此为必填字段"；提交被阻止；其他已填写字段内容保留 |

#### AC-F2-04：保存并恢复草稿

| 条件 | 描述 |
|------|------|
| **Given** | 用户正在填写表单，已输入部分内容 |
| **When** | 用户点击"保存草稿" |
| **Then** | 系统保存当前填写内容，提示"草稿已保存"；用户可在"我的草稿"列表中找到该记录 |
| **When** | 用户稍后从"我的草稿"点击该草稿 |
| **Then** | 系统恢复所有已填写字段内容，用户可继续填写 |

#### AC-F2-05：撤回提交

| 条件 | 描述 |
|------|------|
| **Given** | 用户已提交表单，当前审批人尚未处理 |
| **When** | 用户在审批进度页面点击"撤回"并确认 |
| **Then** | 表单状态变为"草稿"（保留已填内容），审批链重置，审批人收到撤回通知 |

#### AC-F2-06：审批进度可见

| 条件 | 描述 |
|------|------|
| **Given** | 用户已提交表单，审批链为"直属上级 → IT 负责人" |
| **When** | 直属上级审批通过后 |
| **Then** | 用户界面显示：第一级审批 ✔（通过）→ 第二级审批 ⏳（待处理），审批意见一并展示 |

### 4.4 用户流程

**主流程——填写并追踪一个表单：**

```
1. [入口] 用户从导航菜单进入"可用表单"
2. [浏览] 查看表单列表，按分类筛选或搜索
3. [打开] 点击目标表单，渲染填写界面
4. [填写] 按表单结构逐字段填写
   - 系统实时反馈字段验证状态
   - 联动条件控制字段可见性
   - 中途可随时"保存草稿"
5. [提交] 点击"提交" → 全量校验 → 提交成功
6. [追踪] 界面自动切换到"表单内容 + 审批链状态"视图
   - 可查看各级审批人和实时状态
7. [撤回]（可选）审批人未处理时，可点击"撤回"
```

**错误场景：**

| 场景 | 系统行为 |
|------|---------|
| 必填字段未填写点击提交 | 阻止提交，标红未填字段，滚动至首个错误字段 |
| 文件上传超限（类型/大小/数量） | 上传时即时提示，阻止该文件添加 |
| 网络中断导致提交失败 | 提示"提交失败，请检查网络后重试"，已填内容保留 |
| 草稿对应的表单模板已更新 | 打开草稿时提示"表单模板已更新，部分字段可能有变化"，尽力映射已有数据 |
| 提交时审批人解析失败（如组织架构中找不到匹配的上级） | 提示提交者"审批流程配置异常，请联系管理员"，提交被阻止 |

### 4.5 功能需求

| 编号 | 描述 | 优先级 | 依赖 |
|------|------|--------|------|
| FR-F2-01 | 显示用户有权访问的已发布表单列表 | P0 | — |
| FR-F2-02 | 支持按分类筛选和名称关键词搜索表单 | P0 | FR-F2-01 |
| FR-F2-03 | 根据模板配置渲染表单填写界面 | P0 | F1 表单设计器 |

## 5. F3 — 审批工作流

### 5.1 功能定义

| 属性 | 内容 |
|------|------|
| **功能名称** | 审批工作流 |
| **业务目标** | 表单提交后自动按预设规则流转审批，审批人可在统一界面查看表单内容和做出决策 |
| **用户价值** | 审批流程自动化，消除人工传递；审批人看到完整上下文（表单 + 审批链）；审批进度全员透明 |

### 5.2 用户故事

- 作为**审批人**，我想要**收到新审批请求的通知并一键进入审批界面**，以便及时处理。
- 作为**审批人**，我想要**在审批界面同时看到完整的表单内容和审批链状态**，以便充分了解上下文后做出决策。
- 作为**审批人**，我想要**点击"同意"或"拒绝"并填写审批意见**，以便完成审批决策。
- 作为**审批人**，我想要**将表单退回给提交人并要求修改**，以便在信息不完整或不正确时补正。
- 作为**审批人**，我想要**将审批转交给另一位指定人员**，以便在自身无法处理时分流。
- 作为**审批人**，我想要**看到审批链上所有参与者的审批状态和意见**，以便了解完整的审批上下文。
- 作为**表单填写者**，我想要**在审批过程中实时看到各级审批状态变化**，以便掌握流转进展。

### 5.3 验收标准

#### AC-F3-01：正常审批通过流转

| 条件 | 描述 |
|------|------|
| **Given** | 表单审批链配置为"直属上级 → IT 负责人"，填写者已提交 |
| **When** | 直属上级打开审批，查看表单内容，填写"同意"意见，点击"同意" |
| **Then** | 审批流转至 IT 负责人；提交人看到第一级"已通过"；IT 负责人收到待审批通知 |
| **When** | IT 负责人也点击"同意" |
| **Then** | 审批全部完成；提交人收到完成通知；表单实例状态为"已通过" |

#### AC-F3-02：审批拒绝

| 条件 | 描述 |
|------|------|
| **Given** | 表单已提交至直属上级审批 |
| **When** | 直属上级点击"拒绝"，填写拒绝原因："设备型号不符合公司采购标准" |
| **Then** | 流程终止；提交人收到拒绝通知并可见拒绝原因；后续审批节点不再触发 |

#### AC-F3-03：退回修改

| 条件 | 描述 |
|------|------|
| **Given** | 表单已提交至直属上级审批 |
| **When** | 直属上级点击"退回修改"，填写退回原因："请补充设备序列号" |
| **Then** | 表单回到提交人处，状态为"待修改"；提交人可修改后重新提交，审批链从头开始 |

#### AC-F3-04：转交审批

| 条件 | 描述 |
|------|------|
| **Given** | 表单当前在直属上级"张三"处待审批 |
| **When** | 张三点击"转交"，选择"李四"，填写转交原因："我下周出差，请李四代为审批" |
| **Then** | 审批任务转移至李四；李四收到转交通知；审批链记录转交历史 |

#### AC-F3-05：撤回

| 条件 | 描述 |
|------|------|
| **Given** | 填写者已提交表单，第一级审批人尚未处理 |
| **When** | 填写者点击"撤回"并确认 |
| **Then** | 审批流转取消，审批人收到撤回通知，表单恢复为草稿 |

#### AC-F3-06：动态解析审批人

| 条件 | 描述 |
|------|------|
| **Given** | 审批节点配置为"直属上级"（按组织架构动态解析），填写者王五是员工 |
| **When** | 王五提交表单 |
| **Then** | 系统根据组织架构数据解析出王五的直属上级为赵六，审批任务派给赵六 |

### 5.4 用户流程

**审批人审批流程：**

```
1. [入口] 审批人收到通知 → 点击进入"待审批"列表
2. [查看] 点击待审批项 → 进入审批界面
   - 左侧/上方：完整的表单内容（只读）
   - 右侧/下方：审批链状态视图（各级审批人、状态、意见、时间）
3. [决策] 审批人在操作区选择：
   - [同意] → 填写意见 → 确认 → 流转至下一级或完成
   - [拒绝] → 填写拒绝原因（必填）→ 确认 → 流程终止
   - [退回修改] → 填写退回原因（必填）→ 确认 → 退回提交人
   - [转交] → 选择转交人 → 填写原因 → 确认 → 任务转移
4. [完成] 操作后刷新待审批列表
```

**提交人追踪流程：**

```
1. [入口] 进入"我的提交"列表，查看各表单审批状态
2. [查看] 点击某条提交 → 进入追踪视图
   - 表单内容（只读）+ 审批链状态
3. [操作] 
   - 审批中且未处理 → 可"撤回"
   - 退回修改 → 可"编辑并重新提交"
   - 已通过/已拒绝 → 只读查看
```

**错误场景：**

| 场景 | 系统行为 |
|------|---------|
| 审批人尝试审批已被他人转交走的任务 | 提示"该审批任务已被转交给 [某用户]" |
| 审批人规则解析失败（组织架构中查无此人/角色无人匹配） | 审批任务进入"异常"状态，通知管理员 |
| 审批人退回时未填写退回原因 | 阻止操作，提示"请填写退回原因" |
| 提交人尝试撤回已被处理的提交 | 提示"该提交已被审批人处理，无法撤回" |
| 并发审批（如同一审批节点多人） | 任一审批人处理后，任务从其他人的待审批列表移除 |

## 8. F6 — 权限管理

### 8.1 功能定义

| 属性 | 内容 |
|------|------|
| **功能名称** | 权限管理 |
| **业务目标** | 管理员可自定义角色并分配能力，实现灵活、可扩展的权限控制 |
| **用户价值** | 权限模型适配组织实际结构，避免硬编码导致的权限僵化 |

### 8.2 用户故事

- 作为**系统管理员**，我想要**创建自定义角色（如"HR 表单管理员"）**，以便匹配组织中的实际职能。
- 作为**系统管理员**，我想要**为角色分配具体能力（如创建表单、查看数据、导出数据、管理用户）**，以便精确控制权限范围。
- 作为**系统管理员**，我想要**将角色分配给用户**，以便用户获得相应的操作权限。
- 作为**系统管理员**，我想要**修改或删除已创建的角色**，以便随组织变化调整权限结构。

### 8.3 验收标准

#### AC-F6-01：创建自定义角色

| 条件 | 描述 |
|------|------|
| **Given** | 管理员进入权限管理页面 |
| **When** | 点击"新建角色"，输入名称"HR 表单管理员"，勾选能力：设计表单、查看 HR 分类数据、导出数据 |
| **Then** | 新角色创建成功，出现在角色列表中 |

#### AC-F6-02：分配角色给用户

| 条件 | 描述 |
|------|------|
| **Given** | 存在角色"HR 表单管理员"和用户"张三" |
| **When** | 管理员在用户管理中为张三分配"HR 表单管理员"角色 |
| **Then** | 张三下次登录时获得该角色对应的所有能力 |

### 8.4 可分配的能力清单

| 能力 | 说明 |
|------|------|
| 设计表单 | 创建、编辑、签出/签入表单模板 |
| 删除表单模板 | 删除已有表单模板 |
| 导出/导入配置 | 导出和导入表单配置 |
| 填写表单 | 浏览可用表单并填写提交 |
| 审批表单 | 查看待审批列表并执行审批操作 |
| 查看数据 | 查看已提交的表单数据（受数据隔离约束） |
| 导出数据 | 导出数据为 Excel |
| 查看统计 | 访问统计视图 |
| 管理用户 | 用户管理操作 |
| 管理角色 | 角色创建、编辑、删除、分配 |
| 强制签入 | 在异常情况下强制签入被锁定的表单模板 |

### 8.5 功能需求

| 编号 | 描述 | 优先级 | 依赖 |
|------|------|--------|------|
| FR-F6-01 | 提供角色的创建、编辑、删除能力 | P1 | — |
| FR-F6-02 | 每个角色可配置多项能力的开关 | P1 | FR-F6-01 |
| FR-F6-03 | 支持将角色分配给用户 | P1 | FR-F6-01 |
| FR-F6-04 | 支持一个用户拥有多个角色（能力取并集） | P2 | FR-F6-03 |
| FR-F6-05 | 权限变更在用户下次操作时即时生效 | P1 | — |

### 8.6 业务规则

| 编号 | 规则 |
|------|------|
| BR-F6-01 | 权限采用自定义角色模式，非硬编码 |
| BR-F6-02 | 数据隔离规则（F2 系列）独立于角色权限，不可被权限覆盖 |
| BR-F6-03 | 至少需保留一个拥有"管理角色"能力的用户 |

## 12. 边缘情况汇总（跨功能）

| 场景 | 影响功能 | 处理策略 |
|------|---------|---------|
| 组织架构中找不到匹配的审批人 | F3 | 任务进入异常状态，通知管理员 |
| 表单模板在用户填写草稿期间被设计者修改 | F1 + F2 | 打开草稿时提示模板版本差异，尽力映射数据 |

| 同时向同一审批人派发大量审批任务 | F3 | 待审批列表支持分页，无性能降级 |
| 移动端处理包含大表格/子表单的表单 | F2 | 子表单区域支持横向滚动 |
| 配置文件导入到不兼容版本的系统 | F1 | 校验版本并拒绝导入，提示兼容性信息 |
