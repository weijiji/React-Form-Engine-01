## 1. 用户画像 (Personas)

### 1.1 核心角色概览

| 角色 | 技能水平 | 使用频率 | 设备 | 核心目标 |
|------|---------|---------|------|---------|
| **模板设计者** | 基础电脑用户（会用邮件、填表、浏览网页） | 每周 1-2 次 | 桌面端（大屏显示器） | 用最少的步骤创建简单表单，无需学习编程 |
| **表单填写者** | 通用办公用户 | 按需（收到表单链接时） | PC + 移动端（375px-1920px） | 快速、正确地完成填写并提交 |
| **审批人** | 中高层管理者 | 每日多次 | 移动优先 + 桌面 | 快速获取上下文，一键审批，不被细节拖慢 |
| **运维人员** | IT 专业人员 | 低频（模板迁移时） | 桌面端 | 安全、可追溯地将模板从 UAT 迁移到 PROD |
| **系统管理员** | IT 专业人员 | 低频（配置变更时） | 桌面端 | 灵活管理角色权限 |

### 1.2 精细画像：模板设计者（核心角色）

```
姓名：张敏
角色：行政主管 / 部门流程管理员
年龄：35 岁
技术能力：会用 Excel 做表格、用企业微信/钉钉、用浏览器填表单、收发邮件
不会：编程、SQL、逻辑表达式、数据库概念

日常场景：
  周一早上，HR 通知需要一个新的"远程办公申请"表单。
  张敏打开系统，希望能像"跟同事描述需求"一样创建这个表单：
  "我需要一个远程办公申请表单，包含申请人姓名、部门、
   远程办公日期、原因，由直属上级审批。"

心理模型：
  - 把表单想象成纸质表格的线上版
  - "我需要哪些信息？" → 决定有哪些字段
  - "谁需要批准？" → 决定审批人
  - 不理解"条件联动"、"字段可见性"等概念
  - 遇到复杂界面会感到焦虑，倾向放弃或求助

痛点：
  - 不确定字段类型选什么（"文本输入"和"多行文本"有什么区别？）
  - 不知道哪些字段应该设为必填（"全选必填总没错吧？"）
  - 不理解章节分组的用途
  - 担心错误操作导致数据丢失
```

### 1.3 精细画像：审批人（移动优先角色）

```
姓名：李建国
角色：部门总监
年龄：45 岁
技术能力：使用智能手机处理大部分工作，偶尔用电脑

日常场景：
  会议间隙掏出手机，看到推送通知：
  "王伟提交了设备采购申请 — ¥15,000 • 3 件设备"
  点击"同意"，输入意见"批准"，完成。
  全程不超过 30 秒。

痛点：
  - 在手机上滚动长表单很痛苦
  - 审批列表太长时找不到重点
  - 希望一眼看到关键信息（谁、什么事、多少钱）
  - 拒绝时需要快速表达原因
```

### 1.4 设备语境矩阵

| 场景 | 模板设计者 | 表单填写者 | 审批人 |
|------|-----------|-----------|--------|
| **创建内容** | 🖥 桌面（大屏 + 键鼠） | 📱🖥 PC + 移动 | — |
| **浏览/发现** | 🖥 桌面 | 📱🖥 PC + 移动 | 📱 移动优先 |
| **核心操作** | 🖥 桌面 | 📱🖥 填写：PC 为主，移动可完成 | 📱 审批：移动为主 |
| **查看状态** | 🖥 桌面 | 📱🖥 均可 | 📱🖥 均可 |

## 2. 信息架构 (Information Architecture)

### 2.1 导航模型（权限码驱动）

导航为**一份统一侧边栏**，按用户权限码过滤显示项（ADR-0010）；不再是「按角色硬编码不同门户」。不同角色因持有不同权限码而看到不同分区。

```
┌─────────────────────────────────────────────────────┐
│  模板设计者 (UAT)              表单填写者             │
│  ┌──────────────┐            ┌──────────────┐       │
│  │ 📝 我的模板   │            │ 📋 可用表单   │       │
│  │ ➕ 创建模板   │            │ 📄 我的草稿   │       │
│  │ 📦 草稿模板   │            │ 📬 我的提交   │       │
│  │ 📤 导出配置   │            │ 🔔 通知中心   │       │
│  └──────────────┘            └──────────────┘       │
│                                                      │
│  审批人                        管理员/运维            │
│  ┌──────────────┐            ┌──────────────┐       │
│  │ ⏳ 待审批     │            │ ⚙️ 用户管理   │       │
│  │ ✅ 已审批     │            │ 🔑 角色权限   │       │
│  │ 🔔 通知中心   │            │ 📊 数据管理   │       │
│  └──────────────┘            │ 📈 统计看板   │       │
│                              │ 📥 导入配置   │       │
│                              └──────────────┘       │
└─────────────────────────────────────────────────────┘
```

### 2.2 设计理念

- **非必要不展示**：设计者看不到"待审批"菜单，审批人看不到"我的模板"菜单
- **视觉焦点**：每个角色打开系统，第一眼看到的就是他最常操作的内容
- **导航深度 ≤ 2 层**：避免深层嵌套

## 3. 用户旅程 (User Journeys)

### 3.1 旅程 1：模板设计者创建并发布表单

```
阶段              情绪曲线      触点

发现入口           😊 中性      导航菜单"创建模板"
↓
描述需求           😊 轻松      NL 对话界面——像聊天一样描述表单
↓
AI 生成预览        🤩 惊喜      系统自动生成表单结构，即时预览
↓
微调确认           😐 中性      可视化编辑器——重命名字段、调整顺序
↓
配置审批人         😐 略困惑    选择审批人（有默认推荐：直属上级）
↓
发布               😌 满足      点击"发布"→ 确认 → 成功提示
↓
邀请测试           😊 满足      复制链接分享给 UAT 测试用户

关键触点设计原则：
  - NL 对话界面是降低门槛的核心——用户不需要理解"字段类型"
  - 微调编辑器只暴露必要操作（标签、必填、删除）
  - 审批人默认推荐"直属上级"，减少决策负担
```

### 3.2 旅程 2：表单填写者完成填写

```
阶段              情绪曲线      触点

浏览表单列表       😊 中性      按分类浏览 + 搜索，表单卡片清晰
↓
打开表单           🙂 轻松      表单渲染，字段逐个排列，必填标记清晰
↓
填写过程           😐 中性      实时验证反馈，问题立即标红提示
↓
中断（接电话）     😰 焦虑      —
↓
恢复填写           😌 安心      自动恢复：横幅提示"已恢复上次填写内容"
↓
提交               😊 满足      全量校验 → 成功 → 显示审批进度
↓
追踪审批           😐 等待      审批链时间线，状态实时更新
↓
收到完成通知       😄 完成      通知中心 + SSE 实时推送

关键触点设计原则：
  - 自动保存每 30 秒触发一次（字段变更时）
  - 恢复时横幅提示 + 保留所有已填内容
  - 必填字段在提交时才强制校验（填写中不阻断）
  - 提交后直接展示审批时间线，无需跳转
```

### 3.3 旅程 3：审批人移动审批

```
阶段              情绪曲线      触点

手机收到推送       😐 中性      通知栏：摘要 + 直接操作按钮
↓
点击通知           😊 高效      直接打开审批页，摘要卡片优先展示
↓
查看摘要           😊 满意      关键字段一目了然（谁、什么事、多少钱/日期）
↓
同意               😊 高效      [同意] 按钮 → 填写意见 → 确认
↓
完成               😌 满足      返回待审批列表，该条已消失
↓
(备选) 拒绝        😐 略犹豫    [拒绝] → 必填原因 → 二次确认 → 完成

关键触点设计原则：
  - 移动端审批页面顶部是摘要，不是完整表单
  - "同意"一步完成（可选填写意见）
  - "拒绝"必须填写原因 + 二次确认（高安全）
  - 操作后立即刷新待审批列表
```

### 3.4 旅程 4：模板迁移（UAT → PROD）

```
阶段              情绪曲线      触点

UAT 设计者导出     😊 中性      我的模板 → 导出 → 下载 JSON 文件
↓
运维收到配置       😐 中性      接收文件，登录 PROD 环境
↓
PROD 导入          😐 谨慎      导入配置 → 预览变更 → 确认
↓
系统处理           😊 自动      自动下架旧版本 + 上线新版本
↓
确认               😌 满足      迁移记录可见，历史实例不受影响
```

#### 布局

```

│  └ 多行文本   │  │  表单渲染效果    │    │  │ ├ 基本信息   │  │

│  └ 日期时间   │                         │  │ 必填: ☑     │  │
│              │                         │  │ 占位提示:    │  │
│  高级控件     │                         │  │ 请输入姓名   │  │
│  ┌ 文件上传   │                         │  └────────────┘  │
│  └ 人员选择   │                         │                  │
│              │                         │                  │
└──────────────┴──────────────────────────┴──────────────────┘
```

#### 布局理念

| 区域 | 角色 | 交互方式 |
|------|------|---------|
| **左侧：组件面板** | 字段来源 | 点击或拖拽字段类型到画布/结构树 |
| **中间：实时预览** | 视觉焦点 | 表单渲染效果，所见即所得 |
| **右侧：结构树 + 属性** | 精确控制 | 结构树管理层级和排序；属性面板编辑选中字段 |

#### 拖拽交互

- **拖拽库**：@dnd-kit
- **拖入路径**：组件面板 → 拖拽 → 放置到结构树或预览指定位置
- **排序**：结构树中拖拽字段调整顺序
- **跨层级**：支持将字段拖入/拖出章节容器

#### 预览双模式

| 模式 | 说明 | Store |
|------|------|-------|
| **静态预览** | 只读渲染，展示表单结构 | 不维护独立 state |
| **交互测试** | 可真实填写、触发验证、测试联动 | 独立 FormStateManager 实例 |

#### 编辑同步机制

```
用户修改属性 → 更新 DesignStore schema → 预览区自动重新渲染
延迟目标：< 100ms（零延迟感知）
```

#### 填写引导机制

| 机制 | 说明 |
|------|------|
| **章节描述** | 每个章节标题下有简要说明（如"请填写设备的基本信息"） |
| **必填标记** | 红色星号 + 标签加粗 |
| **帮助文本** | 字段下方灰色小字（如"请输入11位手机号码"） |
| **进度指示** | 多章节表单显示"第 X 步 / 共 Y 步" |
| **即时反馈** | 字段失焦时校验，错误标红 + 错误信息 |

## 5. 交互设计规格 (Interaction Design)

### 5.1 核心交互原则

| 原则 | 说明 | 应用 |
|------|------|------|
| **即时反馈** | 每个操作在 100ms 内给出系统响应 | 设计器属性修改、表单字段输入、审批按钮 |
| **高容错** | 破坏性操作必须确认 + 可逆 | 删除字段、拒绝审批、下架模板、删除草稿 |
| **渐进呈现** | 默认展示关键信息，详情按需展开 | 移动端审批摘要 → 完整表单、属性面板基础 ↔ 高级 |
| **防错优于纠错** | 在错误发生前阻止 | 提交前全量校验、签出冲突提示、文件类型校验 |
| **自动保存** | 用户不丢失数据 | 填写过程中每 30 秒自动保存草稿 |

### 5.2 确认与安全

| 操作 | 确认级别 | 行为 |
|------|---------|------|
| **保存草稿** | 无确认 | 即时保存 + Toast 提示 |
| **提交表单** | 隐式确认 | 按钮变为"提交中..."，禁用重复点击 |
| **拒绝审批** | 二次确认 | 必填原因 → 确认对话框 → 执行 |
| **退回修改** | 二次确认 | 必填原因 → 确认对话框 → 执行 |
| **删除草稿** | 确认 | 对话框："确定删除此草稿？此操作不可撤销。" |
| **下架模板** | 确认 | 对话框："下架后用户将无法提交新的申请，历史数据仍可查看。" |
| **删除字段** | 确认 | 对话框（仅当字段含有配置时） |
| **撤回提交** | 确认 | 对话框："撤回后审批流程将取消，你可重新编辑后再次提交。" |

### 5.3 微交互规范

#### 拖拽反馈（设计器）

```
拖拽开始：被拖拽项半透明 + 蓝色虚线边框
悬停目标：放置区域高亮（蓝色背景 10% 透明度）
放置成功：字段出现在目标位置 + 预览区同步更新
放置失败：字段弹回原位 + 轻微抖动动画
```

#### 验证反馈（填写器）

```
字段失焦 → 即时校验
  ✅ 通过：字段边框变绿 1 秒后恢复默认
  ❌ 失败：字段边框变红 + 下方错误文案 + 图标闪烁
  ⚠ 警告：字段边框变黄 + 下方提示文案

提交时全量校验
  ❌ 有错误：滚动到第一个错误字段 + 页面顶部错误摘要条
  ✅ 全部通过：提交按钮变"提交中..."
```

#### 加载状态

```
列表加载：骨架屏（灰色占位块）→ 内容淡入
表单提交：按钮显示旋转动画 + "提交中..."
文件上传：进度条 + 百分比
审批操作：按钮变"处理中..."
```

### 5.4 手势与快捷键（移动端 + 桌面端）

| 平台 | 动作 | 行为 |
|------|------|------|
| 移动端 | 下拉 | 刷新列表 |
| 移动端 | 左滑 | 草稿列表项：显示"删除"操作 |
| 桌面端 | `Ctrl+S` | 设计器中保存 Schema |
| 桌面端 | `Ctrl+Z` | 设计器中撤销上一步操作 |
| 桌面端 | `Esc` | 关闭对话框 / 取消拖拽 |

## 6. UX 规则 (UX Rules)

### 6.1 空状态规则

| 场景 | 空状态展示 |
|------|-----------|
| **新用户首次打开——无可用表单** | 🗂 大图标 + "还没有可用的表单" + "当管理员创建并发布表单后，它们会出现在这里" + 无 CTA（用户无创建权限） |
| **新设计者——无模板** | 📝 大图标 + "你还没有创建模板模板" + [创建第一个表单] CTA 按钮 |
| **草稿箱为空** | 📄 图标 + "没有待完成的表单" + "填写表单时，系统会自动保存你的进度" |
| **提交列表为空** | 📬 图标 + "你还没有提交过表单" + [浏览可用表单] CTA |
| **待审批为空** | ✅ 图标 + "没有待审批的事项" + "真棒！所有审批都已处理完毕" |
| **搜索无结果** | 🔍 图标 + "没有找到匹配的结果" + "试试其他关键词？" |

### 6.2 错误状态规则

| 场景 | 错误处理 |
|------|---------|
| **网络中断** | 内联提示条："网络连接异常，你的数据已安全保存在本地" + 重试按钮 |
| **提交失败** | 保留已填内容 + Toast："提交失败，请检查网络后重试" + 重试按钮 |
| **审批人解析失败** | 阻止提交 + Alert："审批流程配置异常，请联系管理员" |
| **文件上传超限** | 上传时即时拦截 + 提示具体原因（"文件大小不能超过 10MB"） |
| **权限不足** | 404 风格页面："你没有权限访问此页面" + 返回首页链接 |

### 6.3 数据保真规则

| 规则 | 说明 |
|------|------|
| **草稿自动保存** | 每 30 秒（字段变更时）自动保存到服务端；本地 localStorage 实时备份 |
| **草稿恢复** | 打开表单时检测未恢复的本地备份 → 横幅提示"检测到上次未完成的填写，已为你恢复" |
| **表单版本隔离** | 草稿关联的模板更新后 → 打开草稿时提示"表单模板已更新，部分字段可能有变化" + 尽力映射已有数据 |
| **浏览器关闭保护** | `beforeunload` 事件："有未保存的内容，确定离开吗？"（仅当有未保存的变更时） |
| **草稿保留期限** | 2 年，超期自动清除（清除前 7 天通知用户） |

### 6.4 移动端适配规则

| 规则 | 断点 |
|------|------|
| **PC 布局** | ≥ 768px — 多列布局、侧边栏可见 |
| **移动端布局** | < 768px — 单列布局、导航折叠、底部固定操作栏 |
| **最小支持宽度** | 375px（iPhone SE 尺寸） |
| **触摸目标** | 所有可点击元素 ≥ 44×44px（iOS HIG 标准） |
| **文件上传** | 移动端调用设备相机或文件选择器 |

### 6.5 可访问性规则

| 规则 | 标准 |
|------|------|
| **颜色** | 错误状态不仅依赖颜色（红色边框 + 图标 + 文字三重传达） |
| **键盘** | 设计器所有操作可通过键盘完成（Tab 导航 + 快捷键） |
| **焦点** | 表单字段焦点状态有可见的蓝色外框（`:focus-visible`） |
| **对比度** | 文字与背景对比度 ≥ WCAG AA（4.5:1） |
| **文案** | 按钮文案使用动词（"提交申请"而非"确定"），图标配文字标签 |

## 7. 与设计规格的关键差异 (UX vs Technical Design)

| 维度 | 设计规格 (v1.0) | UX 规格 (本文件) | 差异原因 |
|------|----------------|-----------------|---------|
| **设计器布局** | 组件面板 → 画布 → 属性面板/预览 | 组件面板 → 实时预览（居中）→ 结构树+属性 | 预览居中为视觉焦点，用户始终看到最终效果 |
| **拖拽库** | HTML5 Drag and Drop / 轻量库 | **@dnd-kit** | 用户明确指定 |
| **预览** | 静态只读预览 | 静态预览 + **交互测试模式**（独立 store） | 设计者需要真实填写来验证联动逻辑 |
| **创建入口** | 空白画布 | NL 对话生成 + 画布微调 | 目标用户为基础电脑用户，需降低门槛 |
| **审批移动端** | 描述为"移动端适配" | **移动优先设计**（摘要优先 + 一键操作） | 审批人以移动端为主战场 |
| **空状态** | 未涉及 | 每种场景定义教育型空状态 | 新系统需要帮助用户理解功能 |
| **自动保存** | 仅提到草稿功能 | 双层保存：服务端 30s + 本地实时 | 防止数据丢失，增强信任 |

## 8. 设计原则总结

```
1. 预览居中 — 所见即所得是设计器的灵魂
2. 渐进复杂度 — 默认简单，高级功能按需展开
3. 高容错 — 破坏性操作永远有"反悔"机会
4. 移动审批优先 — 审批人不是桌面用户
5. 教育型空状态 — 空白页面是教学机会
6. 自动保存是底线 — 永远不要因为技术原因丢失用户数据
7. NL 降低门槛 — 让不懂技术的用户也能创建模板
```
