# ADR-0012：模板数据隔离 —— 归属决定读写，view_all 只读

> 日期：2026-08-19
> 状态：已采纳
> 关联：BUG-06（「我的模板」列表无数据隔离）；CONTEXT.md「模板归属与可见性」

---

## 背景

BUG-06 实测发现：`GET /api/v1/templates` 列表只按 `category / status / search` 过滤，**未按创建者隔离**，任意登录账号都能看到（并可能操作）全部模板；`GET /templates/:id` 详情同样无归属校验；`PUT /schema`、`PATCH /meta`、`checkout`、`publish`、`force-unlock` 等写操作只挂了 `authenticate`、**未挂权限码**，理论上任何登录用户（包括「填写者」）只要知道模板 id 就能签出、修改、发布甚至强制解锁他人模板。

单租户内多设计者协作时，这是「越权可见 + 越权可写」双重风险。需要一条明确、可执行的隔离策略作为模板读写权限的根。

## 决策

1. **默认可见范围 = 仅本人**：`GET /templates` 默认 `scope=mine`，按 `created_by = 当前用户` 过滤；「我的模板」语义即个人视图。
2. **「全部模板」视图 = 显式能力**：新增 `scope=all` 查询参数 + 新权限码 `template:view_all`。`scope=all` 需持 `template:view_all`；该码赋给**管理员 + 运维**（用于「模板管理」「模板查看」的只读全量视图），设计者仅能看自己的。
3. **归属是读写的根**：`created_by` 决定边界 —— 创建者可读写自己的模板；`template:view_all` 持有者可**只读**查看全部；其余用户不可见、不可写。
4. **写操作补齐权限码门禁**（此前是越权洞）：
   - `PUT /schema`、`PATCH /meta`、`POST /checkout`、`POST /checkin` → `template:edit`
   - `POST /publish` → `template:publish`
   - `POST /force-unlock` → `template:force_unlock`（此前完全无门禁）
   - `DELETE /:id` → `template:delete`（已有，保持）
5. **错误码语义**：非创建者且无 `template:view_all` 访问详情/写操作 → **404**（与「不存在」不可区分，防枚举）；持 `template:view_all` 但对他人模板写 → **403**（可读不可写）。**409 保留给锁冲突**，不用于归属。
6. **唯一越权例外 = `force-unlock`**：管理员可对他人模板强制解锁（CONTEXT.md 既有「管理员可强制解锁」），但**不可编辑、发布或删除他人模板**。

## 替代方案

- **保持全量可见，仅改标签为「全部模板」**：拒绝。未消除越权可见/可写，只是换了个名字掩盖问题；且与导航里已埋的「我的模板」个人语义冲突。
- **引入「共享/协作」机制（默认本人 + 显式共享给指定人/角色）**：推迟至 Phase 2。MVP 无需协作编辑（已有签出/签入独占锁），引入共享需额外建模共享对象与授权矩阵，范围明显放大。
- **复用现有 `data:view` 作为「看全部」门禁**：拒绝。`data:view` 语义是「查看数据」，复用于模板可见性不直观；新增 `template:view_all` 与现有 `template:*` 命名族一致、可读性更好。
- **只修列表隔离、不补写操作门禁**：拒绝。写操作无权限码是更危险的越权洞，与列表隔离同源（都源于「写路径没挂码/没归属校验」），留到 issue 09 会让漏洞空窗期拉长。

## 后果

- **正面**：`created_by` 成为模板读写的唯一事实来源，列表、详情、写操作三处口径一致；跨账号隔离有明确、可测试的边界（A 创建的模板 B 不可见、不可写）。
- **正面**：`template:view_all` 以权限码（而非角色名）表达「看全部」，与 ADR-0010「权限码是访问唯一事实来源」一致；管理员/运维的只读全量视图可复用同一列表端点，仅靠 `scope` 区分。
- **负面**：需一次 seed 变更（新增 `template:view_all` 权限码并赋给管理员/运维）；`/admin/templates`（现挂 `template:publish`）与 `/ops/templates`（现挂 `data:view`）两个占位页在落地「全部模板」视图时，门禁应改挂 `template:view_all`，否则持 `template:publish` 的设计者会被引向一个自己无权使用的全量页。
- **负面**：`404`（非 `403`）用于「存在但不可见」是刻意选择 —— 牺牲「明确的权限提示」换取「不暴露存在性」；未来读者可能疑惑「为何不是 403」，本 ADR 记录原因。
