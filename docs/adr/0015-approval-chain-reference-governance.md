# ADR-0015：审批链引用治理 —— 用户/角色停用与删除时的生命周期语义

> 日期：2026-08-22
> 状态：已采纳
> 关联：工单 06（审批操作 UI）、工单 10（审批链配置）、工单 22（删除拦截 + 提交兜底）、工单 23（引用检索 + 停用提醒）；BUG-10（快照错位）；CONTEXT.md「审批链引用」「停用」

---

## 背景

审批链配置存储在 `form_templates.approval_chain`（独立 JSONB 列），节点规则通过三种方式指向审批人：**直接引用**（`specific`，指名用户 UUID）、**角色引用**（`role`，按角色 UUID 在运行时解析成员）、**组织引用**（`org_structure`，按提交人的直属上级/部门在运行时解析）。

JSONB 内的引用**无法用数据库外键约束**——一致性只能由应用代码在「删除/停用时」或「提交使用时」兜底。

现状缺陷（2026-08-22 设计评审确认）：

- **删除用户**仅拦截「自己 / 最后一个管理员 / 创建过模板」，不检查是否被审批链引用（`server/src/routes/users.ts:335-363`）；删除角色无任何检查（`roles.ts:159-168`）→ 硬删后留下悬空引用，提交时抛 `APPROVER_RESOLUTION_FAILED`（500）。
- **停用（`is_active=false`）后**：`specific` 与 `direct_manager` 解析完全不看启用状态（`shared/src/approvalResolver.ts:47-51, 67-71`）→ 提交成功、审批记录写给停用用户 → **审批静默卡死**（用户登录不了、动不了）。`role` / `department_manager` 有 `preferActive`，但全员停用时回退选第一个（停用的）。
- 运维真实路径是**停用**而非硬删；硬删是极端操作。

## 决策

### 1. 硬删除拦截

删除用户/角色前检查审批链引用：被任一模板的 `approval_chain` 引用则 **409 拒绝**（先例：`USER_HAS_TEMPLATES`）。角色删除同样检查 `role.roleId`。

### 2. 停用不拦截，但提醒 + 可跳转

停用用户时检测引用并列出「被哪些模板引用」，允许**带引用停用**（离职流程往往等不起先改链），提供跳转到相关模板的入口。

### 3. 提交时兜底：解析到被停用审批人 → 干净业务错误

`resolveApprover` 的 `specific` 分支与 `direct_manager` 解析加 `isActive` 判断：被停用 → 不可解析，提交返回**干净业务错误**（事务回滚、带错误码与可读信息），**不 500、不自动替换**。`role` 保持 `preferActive`，并修「全员停用时回退选停用者」的边角（无启用用户 → 不可解析）。

### 4. 检索工具：覆盖直接引用 + 角色成员，MVP 逐模板改

提供「某用户被哪些模板审批链引用」的检索：直接引用（`specific.userId`）+ 角色成员（`role.roleId ∈ 该用户持有的角色`）。**`org_structure` 不纳入检索**——链不指名用户，改了也没用，靠组织数据与第 3 条兜底。MVP 形态：检索列表 + 逐模板进现有编辑器改；**不做批量替换**（published 模板只读、签出锁，批量改会绕过模板生命周期）。

## 替代方案

- **自动替换**（解析到停用用户 → 换其上级/同角色另一人）：拒绝。篡改「指名审批人」语义，用户看不到被换。
- **停用软拦截**（未处理引用不许停用）：拒绝。离职流程等不起先改链；提醒 + 可跳转已足够。
- **批量替换工具**：拒绝（MVP）。published 模板只读 + 签出/发布流程使批量改需绕过生命周期；待真有「一次离职几十个模板」的频率再评估。
- **把审批链并入 schema JSONB 统一版本化**：拒绝（本轮）。当前独立列工作正常，挪动是纯重构无业务收益；若未来格式演进再评估。

## 后果

- **正面**：离职流程语义明确——停用可带引用、提交被干净拦截、管理员有检索工具；不再出现静默卡死或 500。
- **正面**：与 ADR-0001 一致，解析失败仍在提交事务内、回滚整个提交。
- **负面**：硬删被引用账号需先解链（操作成本，但正确）；检索工具需新增 JSONB 查询端点（`@>` 包含查询，可选 GIN 索引）+ 前端列表/跳转 UI。
- **记录债**：`approval_chain` 无独立 `schemaVersion` / 迁移逻辑——MVP 接受（三种规则类型固定、短期不演进），格式演进时补版本护栏。
