# ADR-0014：草稿模型统一 —— 独立 Draft 实体并入草稿状态 FormInstance

> 日期：2026-08-21
> 状态：已采纳
> 关联：工单 05（表单提交 + 草稿 + 填写器）；需求规格 BR-15 / Q-07；ADR-0004（修订）；CONTEXT.md「Draft」

---

## 背景

工单 05 实现时产生了**两个并存的草稿概念**：

- **草稿状态 FormInstance** —— `POST /instances` 创建，填单页自动保存写 `PUT /instances/:id/values`，提交时在同一事务内转为 submitted 并冻结快照。
- **独立 Draft 实体**（`drafts` 表 + `/drafts` API + 「我的草稿」页 + 填单页「保存草稿」按钮）—— 用户手动保存的可恢复快照，2 年过期。

两者在用户界面上撞车：自动保存的内容落在「我的提交」里（按状态筛选才可见），「我的草稿」只显示手动保存的副本；同一份填写可有两份相互独立、可能分叉的拷贝；点两次「保存草稿」产生重复行；恢复草稿派生新实例而不删除原草稿。而需求规格自始至终把草稿表述为「**表单实例草稿**」（BR-15、Q-07）——独立 `drafts` 表是工单 05 实现时对规格的偏离。

## 决策

**草稿 = 草稿状态的 FormInstance，实例即草稿。删除独立 Draft 实体。**

### 1. 删除 Draft 实体

`drafts` 表、`/api/v1/drafts` 路由、`MyDrafts` 页、`/filler/drafts` 路由与导航、「保存草稿」按钮、未生效的 `expires_at` 列全部删除。自动保存是唯一持久化路径（防抖 onChange + 30s 兜底 + 变更检测，无变更不请求；优于工单原稿的 onBlur 触发——捕获每次编辑而非仅失焦）。

### 2. 用户入口合并

「我的提交」改名「我的表单」：列出本人全部实例（含草稿/提交/审批中/已通过…），状态筛选 UI 重做，行点击打开预览弹窗（复用填单页只读渲染）。「我的草稿」入口删除。同一模板允许多份草稿状态实例（多份填写互不干扰，如多张差旅报销单）。

### 3. 版本不匹配迁移作用于草稿状态实例（修订 ADR-0004）

打开草稿实例时**始终执行幂等 fieldId 迁移**（弃时间戳比较与 `_meta`），`_orphaned` 保留在实例 `field_values` 内随自动保存持久化；填单页顶部黄色提示 + 折叠孤儿区。提交时 `_orphaned` 不参与验证与写入（validateAll 按 schema 字段遍历，未知键忽略，以测试确认）。

### 4. 保留策略（落地 BR-15）

仅草稿状态实例参与：按 `updated_at + 2 年` 无活动窗口计算过期（**不新增列**，谓词 `status='draft' AND updated_at < now() - interval '2 years'`）。`GET /instances/my` 过滤过期；打开/保存/提交对过期草稿返回 **410「草稿已过期，无法继续」**；服务器 12h `setInterval` 批量清除；过期草稿直接消失（不显示灰色标签）。已提交实例是审批/审计记录，永久保留。

### 5. 读取权限收紧

`GET /api/v1/instances/:id` 增加属主校验（此前任何登录用户可读任意实例）。审批人读取提交内容留给工单 06 自己的路由（按当前审批节点授权）。

### 6. 提交语义明确

提交事务为「UPDATE 实例（状态 + 冻结 `template_snapshot` + `version + 1`）+ INSERT approval_records」，在同一 DB 事务内完成；审批人解析在事务内、失败回滚（ADR-0001 边界不变）；通知持久化 + SSE push 事务后异步。无审批链的模板提交后直接置 `approved`。

## 替代方案

- **保留双草稿模型、修接缝**（「我的草稿」同时列出草稿实例 + 手动快照、保存草稿按 `(user, template)` 幂等、恢复即删除）：拒绝。用户心智中"草稿"只有一个，两个概念并存且 UI 相同无法区分；需求规格本就只定义一种草稿。
- **草稿全部改回独立实体、实例只在提交时创建**：拒绝。填单中途的自动保存无处安放（实例尚未创建），且提交原子性被拆成"创建 + 提交"两步。
- **过期草稿显示灰色只读标签**：拒绝。过期数据无法继续填写，留着误导用户；静默消失 + 410 明确提示更诚实。数据在过期前有 2 年窗口可保存/提交。

## 后果

- **正面**：消除双草稿分叉与重复；「我的表单」单入口覆盖全部填写状态；自动保存即草稿，无数据可丢。
- **正面**：版本不匹配迁移对**所有**草稿生效（此前只对独立 Draft 生效，草稿实例静默退化）；`_orphaned` 随自动保存持久化，数据真正不丢。
- **正面**：BR-15 首次落地（此前 `expires_at` 写了从未使用）；实例表不新增列，过期用谓词计算。
- **负面**：删除 `/drafts` API 与 Draft 相关 UI 需同步清理既有测试（drafts 路由测试随删；实例路由测试增补过期 410 / 迁移落实例 / 孤儿保留断言）。
- **负面**：`GET /instances/:id` 属主校验后，审批人无法直接查看提交详情——由工单 06 补齐其访问路径，期间审批功能未上线，无实际影响。
